# 长对话用户要求保护

## 原问题

最初 task 固定进入上下文，但 follow_up 只把后续请求写入普通消息历史。随着工具结果增多，裁剪可能移除用户追加的“不要修改接口返回格式”。旧摘要只摘录工具结果，无法补回这类要求。

## 本次实现

1. `Store.create` 建立 `task_state`；`Engine.follow_up` 在保存追问前更新它。
2. `task_state.current_goal` 保存最新真实用户请求原文及来源。它不做语义改写；“继续”这样的简短请求仍需要结合先前原文理解。
3. `task_state.requests` 按顺序保存最初任务与每次用户追问，来源为 `initial` 或完整消息列表中的 `message:N`。每条记录带可选 `constraints`、`acceptance_criteria`，只有用户通过 API 明确提供时才填写，不用关键词或模型推断。
4. 用户更正保留新旧记录。提示模型以明确的最新更正为准，歧义则澄清；程序没有自动撤销条件或语义冲突检测器。
5. 模型 save_notes 仅写工作笔记，不能更新 task_state。旧历史和笔记不被用来提取新的用户授权。用户条件也不能越过工具层的审批与权限规则。
6. API 内部生成的审批续跑通知标记 `origin=approval_notice`，不替换用户目标；发送给模型前移除本地 origin 字段，保持标准消息协议。
7. 旧会话在执行前从完整历史重建状态并保存，不需要清空 SQLite 或做表结构迁移。

## 组装顺序与预算

```text
系统规则 + Skills 目录
用户任务保护区（目标 + 所有用户原文 + 显式条件 + 来源）
可容纳的模型工作笔记（不可信）
有剩余额度才添加的旧工具摘录（不可信、有损）
最近的完整历史交互组
```

优先级：保护区与最新完整交互 > 笔记 > 更早完整交互 > 摘录。任何 assistant tool_calls 与相邻 tool 结果都整体取舍。保护区不由模型摘要替换。笔记放不下时可以省略，原值仍保存在会话中。

未开启模型提取时，任务状态上限为序列化后 12000 字符。新增追问若超限，抛出明确错误且不保存这次追问，不删除已有状态。旧会话已经超限时进入明确错误状态，未调用模型或工具。用户可整理完整要求后开启新会话；目前未实现原会话中的人工合并编辑器。

模型 messages 默认序列化后不超过 18000 字符。保护区与最新交互超过这一预算时明确报错，避免悄悄破坏上下文。该预算不包括独立发送的工具 schemas，也不等于 token 窗口；完整请求 token 计数不在本次修改范围。

未开启模型提取时，这是“关键要求无损保留 + 有界历史裁剪/摘录”，没有新增模型请求。可选语义提取已另行实现，开启后的投影、容量和模型调用规则见 [需求提取说明](requirement-extraction.md)。它保证要求被放入模型上下文，不保证模型一定正确理解和遵守要求。

## 验证

新增测试 `tests/test_context_protection.py` 覆盖：

- 默认预算下 40 组长工具交互后，最新要求与显式条件仍保留且工具消息配对完整。
- 连续追问与更正的顺序、来源保留。
- 模型笔记无法修改用户要求；自然语言原文不被关键词拆解。
- 关闭再打开 SQLite 后的状态保留，以及旧会话升级。
- 超限追问不污染已保存会话，超限旧会话在执行前停止。
- JSON 转义开销和总字符预算；不足时显式报错。
- 自动审批通知不替换目标，且本地 origin 元数据不进入模型协议。
- API 可选字段及输入校验。

未进行付费模型长任务效果评测；这些是确定性数据流与协议回归测试。

2026-10-21 验收：Ruff 通过；共 63 项自动化测试，62 通过、1 项因 Windows 符号链接权限跳过；8 个离线集成任务全部通过。没有将这些结果作为模型开发任务成功率。
