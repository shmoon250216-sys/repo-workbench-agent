# 测试审批与执行规格绑定

## 修改原因

原 run_tests 用 session ID + tool call ID 定位审批，只检查 allow，然后按当前 backend 和当前命令执行。审批暂停后如果从 Docker 切换到 trusted-local，旧审批可能授权不同的执行操作。后端不变时，审批期间源代码变化也没有检测。

本次将审批对象改成不可原地替换的执行规格。真正启动的进程需要与用户批准的内容相符；变化时重新进入 waiting_approval。

## 执行规格

`execution.build_plan` 包含：

- schema 版本、会话 ID、工具调用 ID、runner、backend。
- 实际 argv（绝对可执行文件路径）与工作目录。
- 工作区文件清单的整体 SHA-256、文件数量、字节数、排除目录。
- 可执行文件路径和内容 SHA-256；适用时包含 pyvenv.cfg 指纹。
- Docker 本地镜像 ID 与 daemon ID。实际命令使用镜像 ID 和 `--pull=never`，不自动拉取变化的标签。
- 传给子进程的环境变量摘要，不记录环境变量值，保持原有白名单。
- 测试超时与容器名称。

规范化 JSON（排序键、固定分隔符）计算执行规格摘要。摘要用于比较和追溯，不是身份认证或加密。完整规格保存在 SQLite 审批记录中，页面可展开查看。

## 修改后的流程

```text
模型请求 run_tests
  → 校验参数
  → 检查后端和运行环境，生成代码快照及完整规格
  → 查找当前调用对应的审批
      无审批 / 规格改变 / 旧版审批
        → 旧 pending/allow 标为 stale，新建 pending，暂停等待用户
      规格相同且 pending
        → 继续等待同一审批
      deny / consumed
        → 拒绝执行
      规格相同且 allow
        → 再次计算规格，发现变化则重新审批
        → 未变化则条件更新领取授权：allow → consumed
        → 使用批准记录中的 argv 和复核后的环境启动进程
        → 记录测试结果、approval_id、execution_spec_sha256
```

网页批准后仍自动续跑。续跑重新进入 run_tests 核对，不是批准接口直接启动 shell。

`Store.ensure_test_approval` 不覆盖旧审批数据，规格变化会生成新 ID。即便文件恢复成旧内容，也不复活 stale 审批。已领取授权的同一 call ID 不允许再次执行；重试需要模型生成新调用并重新审核。

`Store.consume_test_approval` 用条件 UPDATE 与 rowcount 校验，一份授权只有一个调用者能领取。独立数据库连接竞争也只能成功一次；这个局部保证不代表整个 Agent 已支持多进程调度。

## 快照范围和限制

快照涵盖普通文件的相对路径、文件模式和内容摘要，包括新增、删除、修改和未提交文件。仅保存整体清单摘要及计数，不把文件内容写入审批记录。

排除 `.git`、`.venv`、`node_modules`、`__pycache__`、`.pytest_cache`、`.ruff_cache`、`.runtime` 和实际会话状态目录。规格中列出排除项，避免审批记录和测试缓存更新导致反复失效。依赖目录没有逐文件校验；解释器与 pyvenv.cfg 指纹不是完整依赖锁定或宿主机隔离。

限制为单文件 8 MB、总量 50 MB、5000 文件。遇到超限、不可枚举目录、覆盖范围内的链接/特殊文件时明确拒绝，不截断后继续。

Docker 需要本机 daemon 和已存在的镜像元数据，不可用时在创建可执行审批前拒绝，不降级到宿主机。本轮镜像/后端变化使用替身测试，未进行真实容器运行验收。

快照是内容指纹，不是冻结副本。最终核对与进程启动之间仍有竞态，无法阻止外部进程在核对后或测试期间改文件。更强保证需要后续增加不可变测试副本/隔离工作区。

授权在启动前领取。若启动失败或之后崩溃，不自动退回 allow；“授权已使用”不代表测试通过。中断测试仍按结果未知处理，不盲目重跑。

本轮不处理测试通过后的长期有效性：VS Code 后续修改让旧 passed 失效，仍是下一项工作。

## 验收

新增 `tests/test_execution_approval.py` 17 项，覆盖审批复用、真实命令一致、单次消费、代码/runner/环境/解释器/镜像/后端变化、旧版审批、内容恢复不复活授权、最终复核、增删文件、容量限制、跨会话、独立连接竞争、数据库重开和 Engine 再暂停/恢复。

完整测试 98 项：97 通过、1 项因 Windows 符号链接权限跳过。Docker 及敏感执行分支使用替身；原有集成测试继续使用受控临时仓库测试子进程。没有在真实用户业务仓库中执行测试。
