# 可选经验复用与本地混合检索

## 用户开关

新建任务的“经验复用（读取＋保存）”默认关闭，并且不会继承上一会话的勾选状态。关闭时不检索历史经验、不生成新复盘、不保存新经验；普通会话、工具调用与审批记录继续持久化。已有经验不会被清空。

空闲、等待审批或任务结束后可切换开关，状态通过登录保护的 `POST /api/sessions/{sid}/memory` 保存；运行中返回409，防止执行器与设置更新互相覆盖。关闭会清空当前待注入的经验，后续执行按新设置处理；已经发给模型的内容、已形成的计划及历史回答不能追溯撤回。此前已经保存的经验需另行使用删除接口删除。

## 检索实现

1. MySQL / SQLite `lessons` 是权威数据，先按工作区路径哈希、30天有效期和来源会话过滤，最多100条。
2. 对 summary、failure、remedy、applicability 提取英文标识符和重叠中文双字片段，用 BM25 计算词面分数（k1=1.2，b=0.75）。不把证据ID或向量元数据参与词项匹配。
3. 使用 FastEmbed + ONNX Runtime 在本机CPU运行 `BAAI/bge-small-zh-v1.5`，512维；任务与经验文本不发送到外部Embedding API。
4. 文档向量首次检索时生成，缓存于 `lessons.data._embedding`，携带模型身份、文本哈希及归一化向量。重启后复用；模型身份、文本或维度变化时重建。查询向量只做至多128条的进程内缓存。
5. BM25正分候选和余弦相似度不低于0.6的向量候选各取最多10条，用等权RRF融合：`sum(1/(60+rank))`，取最多3条。余弦阈值不是置信度，0.6只是当前固定基线，不是校准概率。
6. 返回前再次核对记录是否删除或过期，禁止旧缓存复活已删除经验；向量字段不进入模型上下文。
7. 缺少模型、依赖异常或向量无效时降级为BM25，在会话 `memory_retrieval` 和页面中展示。异常信息仅记录类型。

这里没有调用聊天模型做经验适用性审核，也没有新增Milvus。100条规模采用本地精确向量比较，避免引入额外服务。检索查询沿用初始任务和追加用户请求，检索模块最多保留末尾16000字符；模型自身还有tokenizer长度限制，长任务和长经验可能截断，需要后续独立改进查询构造。换用不同权重时应更新模型身份，避免混用缓存。

## 本机安装与复现

```powershell
pip install -e ".[memory]"
$env:PYTHONPATH = 'src'
python scripts/prepare_memory_model.py
python scripts/evaluate_memory.py
python -m unittest discover -s tests -v
```

准备脚本仅下载公开模型文件，运行时 `local_files_only=True`，不自动下载。可用环境变量 `REPO_AGENT_MEMORY_MODEL_DIR` 指定缓存位置，`REPO_AGENT_MEMORY_MIN_COSINE` 调整余弦下限。默认模型缓存位于仓库 `.runtime/memory-model`，不提交Git。现有DeepSeek主模型配置不变。

## 实测结果与限制

固定自建数据：8条经验、16条有目标查询、4条无关查询、2条相反约束查询。实际运行本地Embedding，没有用假向量计算效果。原始数据和逐题输出分别见 `evaluation/memory-dataset.json` 与 `memory-results.json`。

| 方法 | 有目标查询Recall@3 | 有目标查询平均Precision | 无关查询正确返回空 | 冲突查询错误注入 |
|---|---:|---:|---:|---:|
| 原词项交集 | 62.5% | 52.08% | 4/4 | 2/2 |
| BM25 | 81.25% | 48.96% | 4/4 | 2/2 |
| BM25＋本地向量＋RRF | 100% | 60.42% | 4/4 | 2/2 |

Precision分母为实际返回条数，并非固定3。这是小型合成回归集，不是企业真实任务或独立大规模泛化测评；没有证明Agent任务成功率提升。两个冲突样本表明“主题相关”不等于“处理方法适用”，仍需执行模型核对当前约束；没有宣称冲突判断已解决。

完整机制回归154项：153通过、1项Windows符号链接权限跳过，包含真实MySQL、缓存重连、关闭开关无召回/无复盘写入、API认证与运行中切换拒绝等检查。
