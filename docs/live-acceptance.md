# 配置模型后的验收

1. 按 README 配置本机环境变量，使用供应商确认支持 function calling 的模型。不要把 API Key 发到聊天、写到仓库或截图里。
2. 使用 `init-demo` 创建新的可丢弃仓库副本。去掉 `--demo`，先以 disabled 后端启动。提出“查找加法错误，给出修改并解释原因”。
3. 查看轨迹是否由真实模型调用读文件、提案工具；确认 diff 是对实际文件的修改。批准后继续，核实磁盘内容。disabled 下不能显示测试通过。
4. 对可信自建样例启用 trusted-local，或先完成 Docker 实机验证，再运行测试。记录模型版本、任务、成功与失败、步骤、API usage、耗时，保留匿名化工具轨迹。
5. 加入功能开发任务，例如“新增 clamp(value, low, high)，拒绝 low > high，并补充测试”；再加入理解、分页修复和测试审查任务，不只验收加法案例。
6. 多轮追加“解释刚才修改了什么”，验证 session 历史；中途拒绝提案，验证不会落盘；修改待批准文件后继续，验证旧批准被拒绝。
7. 用独立于模型修改范围的验收测试检查补丁，不把模型自己写的测试通过当作唯一标准。至少保留一部分未参与开发的任务，成功率与脚本回归分开统计。

现已完成 DeepSeek 单个合成修复、多轮追问及流式只读冒烟测试，仍不提供泛化成功率、Token 节省或线上业务收益数字。进一步验收时可将实际结果另存 `evaluation/live-results.json`，记录真实模式，不能覆盖离线模式的口径。
