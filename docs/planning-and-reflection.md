# 双模式执行与证据复盘

这次改动解决两类问题：复杂任务缺少明确的剩余步骤；成功修复后的经验不能跨会话复用。它不训练模型权重，也不保证规划比 ReAct 更快或更准。

## 实际执行流程

1. 新建会话选择 `react` 或 `plan_execute`；另行勾选“任务复盘与经验复用”。默认 ReAct、关闭经验复用，避免简单任务额外调用模型。
2. 开启复用时，从同一工作区的 `lessons` 表检索至多 3 条经验。当前已升级为 BM25＋本地向量＋RRF，详见 [混合记忆](hybrid-memory.md)。超过 30 天的不参与检索，每工作区最多保留 100 条。
3. 规划模式额外调用一次模型，Pydantic 严格校验 2—6 个 `goal + acceptance` 步骤；计划写入会话。格式错误进入 `provider_error`，用户可以重试；不会偷偷切回 ReAct。多轮要求超过规划输入容量时明确要求整合，不静默截掉后续约束。
4. Executor 仍使用既有 Function Calling 循环、12 个工具、4 类 Skills、文件权限和人工审批。模型读代码、提出修改、申请执行，再观察工具结果。规划模式不是新增一个拥有更高权限的 Agent。
5. 每个实际工具结果带短证据编号 `_evidence_id: e1`。`record_plan_progress` 只接受当前未完成步骤，引用映射回本会话真实已完成调用；失败、超时、失效结果不能作为完成证据。步骤验收的语义判断仍由模型负责，程序不把“引用存在”等同于“需求一定满足”。
6. diff 和测试审批暂停后，继续既有计划和待执行调用，不重复付费规划。用户追加实际需求时，按请求摘要指纹重新生成计划。当前是顺序计划执行，没有子 Agent 并行，也没有自动改写计划的 replan 工具。
7. 模型提前给最终答复但步骤未完成时，最多反馈纠正 2 次，仍受总步数与 Token 预算约束；继续不完整则标记 `completed_unverified`。不能靠最后一句“完成了”覆盖运行记录。
8. 测试结束后及最终答复前重新核对工作区指纹；代码变化使测试证据失效。最终状态由实际测试/版本记录判定，独立于模型措辞。
9. 开启复盘且预算允许时，模型读取有界任务文本与最近 16 条实际工具观察，返回 `summary / failure / remedy / applicability / evidence_call_ids`。校验证据引用后保存会话复盘；只有完成状态、当前测试通过、引用中含通过的测试证据时，才写入可复用经验。

## 为什么这样约束记忆

- 失败或未验证的总结留在本会话，不自动晋升为“已证实修复方法”。这减少错误建议跨任务传播，但也意味着纯失败经验暂不跨会话召回。
- 测试通过只证明该次执行有通过证据，**不能证明模型总结的因果解释正确**。经验明确作为可疑参考数据注入，必须结合当前仓库重新核验，不能授权写文件或绕过审批。
- 经验不堆积全部历史，不存思维链；完整工具结果仍由原有调用/产物存储承担。短编号通过来源会话关联真实调用，不能跨会话伪造证据。
- `DELETE /api/lessons/{id}` 可删除当前工作区经验，仍需登录；错误经验可移除，后续召回不再使用。
- SQLite/MySQL 共用 Alembic `0002_lessons` 迁移。计划、复盘存会话 JSON，跨会话经验存 `lessons`，原始消息、审批、调用和事件仍在原来的独立表。

## 预算与失败边界

默认累计 API total_tokens 预算为 100,000；网页新任务 30 步，单次 run 的轮间时间预算 180 秒，审批暂停不计入本次 run。规划和复盘的 usage 同样计入。预算在请求之间检查，正在进行的请求可能使累计数超过阈值，不是硬费用上限。

主模型仍使用原有超时/有限重试。规划和复盘适配器最多请求一次、超时 15 秒（评测为 20 秒）；复盘失败保留主任务结果，显示 `reflection_error`，不会为生成总结重新执行编辑。规划不能解决网络故障。停止操作已增加到同批工具之间的检查点，但不是强杀已经运行的工具。

## 可复现验收

```powershell
$env:PYTHONPATH = 'src'
# 加载你本机配置，勿提交密钥
. ./scripts/load-local-config.ps1
python scripts/evaluate_live_modes.py --out evaluation/live-modes-final.json
python scripts/evaluate_live_modes.py --transfer --out evaluation/live-memory-transfer.json
python -m unittest discover -s tests -v
```

`evaluation/live-mode-tasks.json` 固定 4 个自建仓库任务：解析器、分页、重试策略、库存合并。两种模式使用同一任务和预算，各自从干净目录开始，真实调用 DeepSeek；人工审批由测试程序仅在自己创建的目录对 `logic.py` 修改与固定测试命令自动授权。独立断言放在可编辑工作区之外。这里的“真实”指真实模型和代码执行，**材料是合成练习仓库，不是企业工单或 SWE-bench**。

报告区分独立断言通过、工作流完成、工具错误、Token、耗时。保留开发阶段的 25k、60k、100k 预算报告，不把失败删掉。早期规划失败主要来自模型无法稳定引用长调用 ID；显式短证据编号解决了这类参数错误。最终结果见 [评测摘要](../evaluation/planning-summary.md)。

经验实验在同一工作区重置已声明的练习文件，依次执行 seed / without_memory / with_memory。它验证跨会话召回，不能用三个样本声称泛化、自我进化或成功率显著提升。

## 阅读源码

- `deliberation.py`：结构化计划、反思、证据引用、步骤推进。
- `engine.py`：接入位置、审批恢复、预算、完成检查与复盘调用。
- `context.py`：用户要求、计划和经验怎样进入有界上下文。
- `store.py` / `0002_lessons.py`：持久化、过期、容量、同工作区召回与删除。
- `tests/test_deliberation.py`：引用造假、失败晋升、跨工作区隔离、恢复与停止等边界。
