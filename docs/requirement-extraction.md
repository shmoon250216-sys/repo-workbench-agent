# 模型需求提取：配置、数据流与验收

这是可选功能，默认关闭。未配置时原文保护仍可使用；本次没有连接真实模型服务，不声称语义提取准确率或真实 token 节省率。

## 数据流

用户输入 → SQLite 保存原文和显式字段 → 任务执行开始 → 检查提取缓存与触发条件 → 专用模型阅读用户输入并输出 JSON → Pydantic/来源/更正目标校验 → 保存结构化视图及版本 → 组装开发模型上下文。

`task_state.requests` 仍是原始记录。新增 `requirements_view` 是模型生成的工作视图，不是用户授权；`requirements_versions` 保存每次新增、替换前条目与来源。API 查询会话可以查看全部字段，网页事件“需求提取”显示本次状态及提取条目。

提取输出包含 `covered_sources` 和 `items`。条目类型为 goal、constraint、acceptance、background、question，包含 text、source、quote、replaces、correction_quote。条目 ID 由程序生成。新增要求默认追加；替换必须引用已有同类型条目，并提供新用户输入中的更正原文。未提及旧条件不会自动删除。显式 API constraints/acceptance_criteria 独立保留，不允许提取模型覆盖。

每条 quote 必须是对应用户原文的真实子串，来源只能是当前新增的用户记录。仅有 covered_sources 不证明语义覆盖完整；Pydantic 也不能证明摘要含义正确。真实模型仍可能漏掉条件、错解否定或把非更正当成更正，需通过真实样本评测及必要的人为核对验证。权限和编辑/测试审批继续由原工具层控制。

## 触发与成本

- 尚无视图时：任意待处理原文达到 1200 字符，或原始任务状态序列化达到 6000 字符，才触发。
- 有视图后：存在新增用户消息时，使用已有条目和新增原文做一次增量提取。没有新增消息则直接缓存复用，审批恢复不会重复提取已处理来源。
- 简单“继续”可能产生空增量；已有视图时仍会调用一次提取模型，没有用关键词判断语义。
- 每次 run 最多一次提取请求，默认网络超时 15 秒、无自动重试；属于网络 IO 超时，并非完整流式传输的硬墙钟截止。
- 提取模型报告的 usage.total_tokens 计入会话累计用量；未报告 usage 的费用无法精确计量。事件记录来源数、原始/投影视图字符数及是否实际使用视图，这不是 token 节省比例。
- 只有投影视图比原文状态短时才替换上下文。已被投影覆盖的历史 user 消息替换为来源提示，避免长原文在历史中再次重复发送。
- 原文留在 SQLite；新增 `read_user_request(source, offset)` 工具可按来源回读，每次最多 3000 字符，仅访问本会话真实用户记录。

## 容量与回退

网页/API 单次输入最多 16000 字符。未开启功能时仍受原文保护区 12000 字符序列化容量限制；开启后原文存储保护上限扩展为 200000 字符，不代表把这些内容全部发给模型。

单次待提取源记录最多 24000 序列化字符，结构化条目合计最多 6000 字符。若旧会话积累过多未提取原文，本版不会自动分批调用模型，应先整理/拆分任务。消息投影仍受原有 18000 字符预算约束，工具 schema 不在该预算内。

缺配置、超时、响应截断、非法 JSON、未知字段、虚构引用或非法更正都回退：保留上次有效视图，并把尚未成功提取的新请求作为原文加入上下文；首次失败则使用原始任务状态。原文仍放不下时明确报错停止，而不是带着缺失要求继续。关闭功能后新的执行不再使用已有投影视图，但历史视图和原文不会删除。

## 本地配置

参考 `.env.example`。程序不会自动读取 .env 文件；以下变量需在启动工作台的同一个 PowerShell 终端设置。提取模型与开发模型分开配置，可以指向同一供应商，但不会自动复用主模型密钥。

```powershell
$env:REPO_AGENT_REQUIREMENTS_ENABLED = '1'
$env:REPO_AGENT_REQUIREMENTS_BASE_URL = 'https://你的供应商地址/v1'
$env:REPO_AGENT_REQUIREMENTS_MODEL = '支持JSON输出的模型名'
# 不把密钥写入聊天或提交到 Git。以下在本机安全输入：
$requirementKey = Read-Host '需求提取模型 API Key' -AsSecureString
$env:REPO_AGENT_REQUIREMENTS_API_KEY = [System.Net.NetworkCredential]::new('', $requirementKey).Password
```

然后按 README 的命令重新启动真实模式工作台。不要加 `--demo`；演示模式不自动加载提取模型。开发任务继续使用 REPO_AGENT_BASE_URL / REPO_AGENT_MODEL / REPO_AGENT_API_KEY，需要另外配置。

接口采用 Chat Completions 的 `response_format: {"type":"json_object"}`，schema 写入提取提示，并在本地严格验证。没有假设供应商支持原生 strict JSON Schema。供应商不支持 JSON mode 时会回退，需选择支持的接口；不要声称任何 OpenAI-compatible 接口均已验证兼容。

## 配置后的真实验收步骤

1. 在可丢弃的代码仓库中启动工作台，测试执行后端保持 disabled，先提交“只分析、不修改”的任务。
2. 使用带重复背景的长输入（超过 1200 字符），其中明确写入“不得修改数据库”“默认每页20条”“空页返回空列表”。观察“需求提取”事件。
3. 人工核对目标、否定、数字、条件是否完整，来源及原文引用是否正确。extracted 只表示结构/引用检查通过，不等于语义正确。
4. 追加“更正：默认每页50条，其他条件不变”，确认仅对应旧条件被替换，数据库限制仍在，版本里保留旧条目。
5. 检查原文回读、重启后缓存复用；临时设错接口验证回退事件与原文保留。
6. 记录真实请求 token、耗时、遗漏/错误条目；与关闭功能的同一任务对比。不能用合成替身的压缩比例作为模型效果。

## 代码结构

| 位置 | 职责 |
| --- | --- |
| `task_state.py` | 保留用户原文及显式条件，管理存储容量 |
| `requirements.py` | 输出契约、模型传输、来源检查、增量视图和上下文投影 |
| `engine.py` | 每次执行开始准备需求，保存视图并累计用量 |
| `context.py` | 使用有效短视图，替换已覆盖的用户历史，保持工具消息配对 |
| `tools.py` | 受限原文回读 |
| `api.py` / `cli.py` | 注入可选提取器，提供配置入口 |
| `tests/test_requirements.py` | 模拟提取、HTTP 协议、失败恢复、持久化、API/Engine 集成 |

本模块不接触修改权限、不执行工具，也不把模型提取内容当作人工审批。现有其他审核问题不属于本轮修复范围。
